# 实现原理

[返回 README](../README.md) · [插件功能](features.md) · [安装方式](installation.md)

## 组件分工

| 组件 | 职责 |
| --- | --- |
| `inject.py` | 根据游戏版本修改加载命令、写入跳板和功能站点，生成部署清单 |
| `libxrcdemo.dylib` | 初始化面板、处理练习逻辑、时钟、音频和内容功能 |
| `libellekit.dylib` | 提供运行时 hook 支持 |
| `src/core/XRCProfile*.h` | 按游戏版本定义运行时地址与布局 |
| `profiles/ios_7.0.256.json` | 保存 7.0.256 注入地址及原指令指纹 |
| `xrc_patch_manifest.json` | 本地注入结果，包括站点状态和动态库哈希 |

注入器让主程序加载动态库，同时安装判定跳板与 BRK 站点。运行时处理器执行选定功能，再按站点规则重放原指令并返回。动态库、处理器和主程序站点必须配套，不能只更换其中一部分。

注入前核对原字节、跳板空间与动态库功能标记。`--check` 检查静态状态；运行时能力探针验证入口和站点，控制面板功能是否可用。

## 时间与音频

谱面时钟使用倍率后的时间；音乐通过原生音频通道变速，并用 DSP 补偿音高。音频输出缓冲带来的延迟与用户偏移分别处理。

进度条、循环端点使用音频时间。跳转在主线程按事务执行：

1. 记录当前场景、谱面对象、播放器和目标。
2. 请求音频定位，等待真实通道位置确认。
3. 平移谱面时钟，保留音画校准差值。
4. 按需要重置、复活和重建判定对象。
5. 在原生更新后收敛时钟，释放本事务的冻结状态。

忙时保留最后一次手动目标，自动循环不覆盖手动请求。换场景、过期、定位失败和超时均有收尾；旧超时任务不能结束新事务。DSP 延迟按当前倍率折算，避免低倍率回跳时重复补偿。

## 自动适应倍率

设播放倍率为 `r`，用户偏移为 `O`，原流速为 `S`：

| 目标 | 公式 | 实现 |
| --- | --- | --- |
| 保持相同实际偏移时间 | 内部用户偏移 `r × O` | 为谱面时钟增加 `(r − 1) × O`，只写增量 |
| 保持相同实际下落体验 | 内部流速 `S / r` | 在原生音符相对距离转换前乘倍率倒数 |

谱面毫秒随倍率变化，所以用户偏移需要乘倍率才能保留相同的真实时间延迟。谱面自身的 `AudioOffset` 不参与用户偏移补偿。跳转校准扣除自动适配增量，避免切换倍率或反复跳转后累加偏移。

手动输入通过游戏原生 setter 写入并保存 `highspeed_int`，按流速乘十存储，随后回读确认；范围为 `0.1–214748364.7`。游戏显示读取这个原生字段。自动适配不会写入补偿后的设置值。

已加载谱面的基准流速记为 `B`，当前原生设置记为 `S`。普通音符、长条和 Arc 的原生相对距离，在浮点转 int32 前乘 `S / B`；开启倍率适配后乘 `S / (B × r)`。每帧重新计算系数，不累乘上次结果。节点 Z 缩放、渲染深度和原生前后显示窗口保持原值。

当距离系数小于一时，只扩大空间索引候选查询的临时范围，确保原生显示窗口内的音符仍被检索到；查询限定在已有索引键范围内，不改写窗口、索引键或绝对距离。换场景时重新采集索引范围，读取失败时暂缓距离修改并记录日志。跳转期间暂停补偿，在正常更新阶段恢复。

音符距离在原生 int32 转换前饱和，避免极大流速溢出。功能需要六个距离/候选站点、流速显示站点及配套动态库标记 `practice-native-flow v2`；旧的窗口 hook 已停用，不能只更新动态库后沿用旧站点。

Arc 除端点距离外，还保存子段端点和网格。原生过线裁剪只隐藏或修改这些子段，倍率变回去不会自动恢复。`XRCArcFlow.m` 在正常主线程更新前从基准快照恢复八个 Vec3 记录，只调整 Z 距离，再调用原生网格更新入口；保留原始 X/Y、节点缩放和窗口，让原生逻辑重新裁剪。缓存随场景清空，只处理当前渲染注册表内、身份仍匹配的对象。

跳转校准采用七个稳定样本的中位数，至少观察 200 ms；尚未稳定时保留请求，避免把加载或音频落位的单帧误差存为基准。事务期间延后音乐倍率设置，结束时先释放冻结、同步实际倍率并重新对齐，再用两个正常帧确认。插件跳转的位置回退标记由音乐模块确认，结束后的短保护期内不再触发第二次 DSP 位置补偿。

## Konzetsu 效果

谱面加载时捕获选择和开关状态，在音符转换、渲染与血条初始化的限定路径中应用原生效果。真实挑战选择、通关状态及结果流程沿用游戏逻辑。

综合模式对原生支持歌曲使用原时间表。其他歌曲以 Arghena 的效果顺序为模板，按最后一个解析音符起点加 500 ms 缩放时间范围；长尾音频可能不在效果范围内。

挑战选择循环顺序是面板操作，保存后不动态转换当前谱面。游玩隐藏图标依据最近的 GameScene 更新帧判断，不访问退出后的旧场景指针；定时刷新会在帧更新停止后恢复图标。

## 内容与网络

原生热更新目录为 `Library/Application Support/cb`。内容外置功能将其迁移到 `Documents/cb` 并建立数据容器内的链接；有效内容在 `cb/active`，元数据在 `cb/meta.cb`。

应用包和数据容器是不同目录。把热更新文件放在 App 根目录不会自动生成已安装状态。当前部署将热更新作为独立容器导入包，IPA 不重复携带这些文件。

cb 就绪站点重放原生 getter。曾强制返回就绪导致首次启动解析空内容时触发 `IsArray()` 断言，因此校验覆盖、目录存在与内容初始化必须分别判断。关闭整个 `cbBypass` 不是通用修复。

网络重定向处理匹配请求的地址，不替代服务端协议。发布构建缩小网络 hook 范围，避开曾在 iOS 26 启动期间阻塞的全局诊断探针；变更网络钩子仍需启动测试。

## 跨版本适配

完整迁移步骤、源码遗漏点与验收清单见 [游戏版本适配指南](version-adaptation.md)。

**当前分别维护 7.0.255 与 7.0.256；Konzetsu 只提供 7.0.256 配套接口。** 7.0.256 不能复用 7.0.255 动态库或补丁地址。相同版本号的不同修改包也可能有不同布局。

| 步骤 | 核对内容 |
| --- | --- |
| 1. 保存样本 | 已解密主程序、完整原始 App、样本指纹和 Mach-O 布局 |
| 2. 定位接口 | 判定入口、场景更新、时钟、音频、渲染及内容入口 |
| 3. 验证 ABI | 对象字段、vtable 槽、函数参数和返回值 |
| 4. 更新配置 | 同步运行时头文件、注入配置、站点名称和原指令指纹 |
| 5. 分配空间 | 跳板、重放区、slot 和 info blob 不重叠；区分虚拟地址与文件偏移 |
| 6. 检查重放 | PC 相对指令不能直接搬进跳板，必须处理其寻址语义 |
| 7. 构建部署 | 编译该版本动态库，在备份副本注入并执行 `--check` |
| 8. 设备验收 | 启动、判定、跳转、循环、音频、效果与内容分别检查 |

新增站点需同步动态库功能标记与注入配对检查。原字节不符、重放空间被占用或出现计划外 BRK 时，重新检查样本和定位，不绕过断言。

## 构建与测试边界

`XRC_DEBUG` 控制动态库中的诊断内容；注入器 `--profile` 控制主程序功能站点，两者独立。日常使用发布构建及 `release` 配置。

测试覆盖加载命令、版本切换、补丁恢复、挑战映射、偏移与流速数学、跳转边界。Windows 没有 C 编译器时会跳过 C 可执行测试，macOS 工作流执行完整测试。原生流速测试覆盖十分之一整数上限、S/r 方向、距离饱和、低流速候选范围和新旧产物配对；静态与数学测试不能替代设备验收。
