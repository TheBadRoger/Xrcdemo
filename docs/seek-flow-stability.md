# 连续跳转与倍速稳定性

## 问题与处理

- Arc segment `+0x2B4` 的 24 个浮点数是两个端点与六个绝对网格顶点。端点与对应顶点的 Z 必须同步缩放，XY 保留原值，以保持截面厚度；已裁剪的头由原生逻辑控制。同倍率不再逐帧重写网格。切换倍率时按各个 segment 的实际裁剪状态判断，不能用整条 arc 的开始时间替代。
- 时间轴开始拖动时暂停 BGM 和谱面更新；拖动只预览。松手后定位音乐，确认暂停通道位置误差不超过 2ms，再恢复音符和清理判定音效去重记录。期间只更新原生 TimeKeeper，防止恢复时补算拖动耗时。拖动开始前快照游戏根视图，覆盖绘制队列停止提交后的黑帧；定位结束或取消后移除，面板保持实时交互。
- 前跳、回跳和倍速切换均通过同一恢复事务。连续请求保留最后目标，上一事务结束后继续保持暂停，避免中间判定。取消拖动、请求过期与场景变化释放本插件的暂停所有权；原本暂停的播放不会被恢复。
- 重建前恢复旧 segment 的标准几何并清空缓存，重建后在第一次播放更新之前记录新基准，防止将已缩放几何再次当作原始形状。
- 后台检测的旧恢复任务在手动拖动/跳转期间丢弃；恢复继续在主线程串行执行。
- 倍速滑块拖动只预览，松手应用一次并对齐。回到 1x 保留累计 warp epoch，避免直接跳回原始墙钟。DSP 延迟与自适应偏移应用后再进行最终绝对对齐。

- 原生暂停时停止累计 `(1-rate)*delta`。如果整个更新循环被暂停（帧间隔超过 200ms），也不把暂停时长当播放时间。恢复前刷新 TimeKeeper 并按音频位置、DSP 延迟与自适应偏移绝对对齐，原生更新后再收敛两帧。

## 网格修正依据

`0xB00370` 根据输入 Vec3 的 X/Y 添加截面宽度，三个输出顶点的 Z 均直接读取输入 `+8`。`0xF33CC0` 是 Vec3 拷贝构造（从 X1 复制），并非零向量构造。segment 构造 `0xB00844–0xB0091C` 将头/尾顶点分别写入 `+0x2CC` 和 `+0x2F0`，mesh builder `0xB00D4C` 直接将这些绝对顶点复制到绘制缓冲。上一版将它们判成偏移向量导致尾部未随距离倍率变化；本版已纠正，保留每段裁剪检测与同倍率不重写策略。

## 原生入口依据

| 功能 | 7.0.255 | 7.0.256 |
| --- | --- | --- |
| TimeKeeper tick | `0x99A724` | `0x99C884` |
| FMOD ChannelControl::getPaused | `0x10E2DAC` | `0x10E5F0C` |

TimeKeeper tick 前 28 字节唯一匹配两个宿主；该函数从原生时间源刷新 `+32`，更新时仍需通过 `base +40` 对齐。`+45` 是分段时钟标志，不能当暂停位。getPaused 在两个版本均核对调用链、输出参数和原生函数名。BGM group 来自 player `+0x18`；恢复暂停时必须同时匹配 scene/player/group。

## 验证边界

C 回归覆盖端点/网格顶点深度一致与 XY 截面宽度保持、裁剪头、反复换倍率不累乘、暂停跳转拒绝旧位置、暂停所有权、暂停/长间隔恢复条件、1000 次倍率变化与回到 1x 的时钟连续性。C++ 测试覆盖时间拉伸的音高、立体声和 seek 后历史清理。iOS 编译通过在线工作流验证。需要真机继续验证长蛇贴面、连续拖动、暂停菜单中跳转以及快速调速；自动测试不能证明宿主运行时完全正确。
